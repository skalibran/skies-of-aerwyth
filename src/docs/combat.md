# Combat slice

Run `scenes/world/journey.tscn` for a starting fleet of three player Kestrels. Normal play schedules the first enemy wave after 100 meters of travel at logical Z = 0, then raises threat and schedules another wave every 1000 meters. A weighted budget pool and optional guaranteed ship/fleet entries define compositions. See [encounter authoring](encounters.md). There is no automatic casualty replenishment. The bottom ship picker manually adds friendly Kestrels, Swifts, Mantas, and Bastions. Its catalog and random-placement ownership are documented in [UI notes](ui.md#ship-picker). Combat remains enabled for registered hostile ships. Destroyed ships become passive falling wrecks, freeze after three seconds of supported settling, and are removed 25 seconds after first ground contact. Production, purchased reinforcements, defeat screens, water-specific wreck behavior, and combat UI remain unimplemented.

The opt-in extended combat check creates and steps [`CombatSpawner`](../../scripts/tools/combat_spawner.gd) explicitly. This validation helper adds up to ten ships per faction each second and independently replenishes each side to 100 living ships, counting the starting players. Partial batches never exceed the cap, and capped or blocked ticks do not accumulate a later burst. This fixture disables the normal encounter director. Journey processes both ordinary encounter placement and explicit UI requests at physics boundaries.


One world unit is one meter. See the [unit conversion](world_units.md). The combat fixture spawns both factions 1000–1500 horizontal meters from the persistent fleet marker, within 1500 meters above or below its altitude (a 3000-meter vertical band). The ship average and camera position do not move this fixture's spawn region. Origin shifts preserve its position relative to the marker. The fixture authors an 1800-meter minimum fleet radius. Ships outside it enter through the shared bounded navigator.

## Authored ships and weapons

[`kestrel.tscn`](../../scenes/ships/kestrel.tscn) inherits the shared [`ship.tscn`](../../scenes/ships/ship.tscn), replaces its primitive visuals with the authored voxel model, and fits the capsule to that model. It authors its slower [flight tuning](movement.md#forward-flight-and-momentum), owns two tier-one slots, assigns their starting equipment, and authors its combat directions. Both factions instantiate the same scene. Set `entity_id` and `faction` **before adding the ship to the tree**, because readiness initializes weapon phases and tint. Then position the ship and register it with Journey. `player` and `enemy` are hostile to each other. Matching identifiers are allied, and other strings are non-hostile. The existing neutral navigation fixtures remain supported. Live faction switching is not part of this slice.

The balloon and hull OBJ meshes use the existing tenfold import scale: one source voxel is one meter, giving a 23 x 11 x 11-meter balloon and a 20 x 5 x 5-meter hull. The hull sits nine meters below and two meters forward of the balloon, preserving the assembly in `src/models/airships/kestrel.vox`. Both parts are recentered together inside the body and rotated so the pointed bow faces local -Z. The upright body keeps one forward capsule (31 meters long, radius 10.5 meters), sized directly to cover both meshes through their authored pitch/bank range. Source OBJ/VOX files are unchanged.

Both meshes share [`kestrel_palette.tres`](../../materials/ships/kestrel_palette.tres), using the existing [`balanced_palette.png`](../../resources/textures/balanced_palette.png) through their authored UVs. The palette imports losslessly without mipmaps and the material uses nearest filtering, preserving its individual color entries. Imported mesh LODs remain enabled.

### Death smoke authoring

Airship owns the smoke configuration and lifecycle. On Kestrel, **Death Smoke Scene** selects [`ship_death_smoke.tscn`](../../scenes/ships/ship_death_smoke.tscn), and **Death Smoke Points** references `VisualRoot/DeathSmokePoints`. Its direct `Marker3D` children supply positions only: they have no scripts, particle systems, or references to one another. Kestrel currently has just `HullSmoke`. Its balloon source was removed. Move, duplicate, or delete markers in that container to author sources. There is no source array to maintain. A missing/empty container or empty effect scene produces no smoke, while destruction continues normally.

On lethal damage, the ship collects the surviving markers once and creates one effect under its `VisualRoot`. Living ships have no instantiated death-smoke system. Removing an active marker drops that source through its lifetime signal. Removing the last stops the effect. Smoke stops permanently on the first upward static-ground contact. Crashed wrecks retain no smoke, including during settling or after terrain LOD changes. Choose a different scene rooted in `ShipDeathSmoke` on the airship for a different style. Markers remain interchangeable.

The effect's `Particles` child is a native [GPUParticles3D](https://docs.godotengine.org/en/stable/classes/class_gpuparticles3d.html) with 48 particles per source and a five-second particle lifetime. At activation, capacity scales with the surviving source count: Kestrel uses 48 particles in one GPU system, and two markers would use 96. Its shared QuadMesh and billboard material draw camera-facing squares without a texture, lighting, shadows, or particle collision. The shared process material authors upward speed/spread, gentle drift, growth, and a charcoal-to-gray fade. Runtime emits individual puffs at `authored Amount * Amount Ratio / Lifetime` per second from each source, on the physics clock. Native GPU particles handle their subsequent motion and fading. Tune **Amount**, **Lifetime**, and **Process Material** in the reusable scene. Enable **Emitting** temporarily for editor previews and leave it disabled in saved content. **Plume Extent** supplies culling padding for the authored rise and expansion. Increase it if tuning produces a larger plume.

All default emitters share one immutable process material. Manual emission supplies each puff's source position, avoiding per-frame material mutation and render-frame script callbacks. Culling bounds retain the recent particle lifetime in one-second buckets instead of growing for the wreck's entire fall. Particles use a fixed, world-aligned local frame so old smoke remains behind a falling/tumbling ship. FloatingOrigin's completed-shift signal moves that frame through WreckController without restarting the particles. Visibility still inherits from VisualRoot, including LOD hiding. Effects remain children of the ship for teardown. No detached effect nodes or per-particle scripts are created. Hidden and stopped emitters have source updates disabled. `ShipDeathSmoke.is_emitting()` reports active smoke. The native `Particles.emitting` remains false because emission is submitted explicitly. This uses the project's Forward+ renderer.

Hiding a wreck also disables smoke emission and source updates. On reveal, the emitter clears its suspended GPU particles and restarts at the current source position, preventing old puffs from reappearing after a long LOD interval. Visibility changes cannot start smoke before death or restart it after impact. Camera picking skips dead hulls, including hidden ones, while island collision still blocks selection. Physical wreck contacts remain active until settling finishes.

### Cannon shot smoke

Rusty cannon assigns [`cannon_shot_smoke.tscn`](../../scenes/weapons/cannon_shot_smoke.tscn) to MountedWeapon's **Shot Smoke Scene**. Assign that same scene on other selected cannon scenes to reuse the effect. Leave the property empty for weapons without muzzle smoke. A different smoke style can use a separate scene rooted in `CannonShotSmoke`, with its own material and tuning. This is presentation configuration on the equipped cannon, separate from its shared ballistic definition.

Each successful shot emits six pale, growing and fading square puffs from the actual muzzle along the solved firing direction. Puffs last 0.75 seconds, slow down, and drift upward. Rejected shots and cooldown checks emit nothing. The reusable scene exposes **Puffs Per Shot**, **Speed Range**, **Spread Degrees**, **Plume Extent**, particle **Lifetime**, and the shared motion/draw materials. **Amount** is the total cosmetic capacity for that style (2048 by default), not a per-cannon count. Excess bursts are skipped without suppressing projectiles or changing damage/reload.

ProjectileController lazily owns one GPU batch for each selected smoke scene across all ships. Smoke remains in world space after the cannon moves or disappears, and its local particles inherit the projectile root's floating-origin shifts. Bounds track only unexpired bursts. Idle batches hide and stop processing. `clear()` removes active shot smoke together with projectiles, and scene exit releases the batches. The first burst after activation waits for GPU buffer initialization before submitting particles. Shared unlit materials, no particle collision/shadows, and no per-shot scene instances keep the presentation cost bounded.

### Factions and mounted equipment

[`Factions`](../../scripts/combat/factions.gd) owns that relationship rule. Enemy geometry uses a shared translucent reddish material overlay. The original meshes/materials remain shared and unmodified. Player tint, instance health, and mount cooldowns cannot leak between ships.

Each ship-owned [`MountedSlot`](../../scripts/ships/mounted_slot.gd) has a tier, authored orientation, cone half-angle, pass-by targeting preference, and an optional `equipment_scene`. The reusable [`mounted_slot.tscn`](../../scenes/ships/mounted_slot.tscn) starts empty. A scene assigned to it must have a [`MountedEquipment`](../../scripts/equipment/mounted_equipment.gd) root with a valid [`EquipmentDefinition`](../../scripts/equipment/equipment_definition.gd) of exactly the same tier. This contract supports weapons and utility equipment. Utility effects themselves are not implemented in this slice.

Kestrel's `LeftSlot` and `RightSlot` each assign [`rusty_cannon.tscn`](../../scenes/weapons/rusty_cannon.tscn) as their initial equipment. Its [`MountedWeapon`](../../scripts/weapons/mounted_weapon.gd) owns the cannon model, aim pivot, ballistic targeting, and independent reload/search state. It references the shared weapon definition and asks its slot whether the launch direction is allowed. The cannon scene has no Kestrel reference and can be assigned to any matching slot.

In the Godot Inspector, select either slot in `kestrel.tscn` to edit **Tier**, **Equipment Scene**, and **Cone Half Angle**. Clear Equipment Scene to leave a slot empty, or assign a compatible equipment scene. At runtime, `assign_equipment(scene)` returns false for incompatible equipment and preserves the current assignment. Replacement creates fresh equipment state, reapplies faction tint, and resets combat positioning. Empty and utility-only ships continue travel. Changing a slot's tier clears incompatible equipment.

The editor-only **Show Cone Preview** draws a translucent `CylinderMesh` with its top radius set to zero. Adjust Cone Half Angle or rotate the slot to author the firing angle. **Cone Preview Size** controls its side length for readability, not weapon range. Preview geometry is generated from the same angle as the firing test, is not saved into the scene, and is absent at runtime.

The slot origin is the equipment origin, muzzle, and cone apex. The current authored Kestrel tuning places cannons beside the gondola at local X = +/-3, Y = -5, Z = 0.75 meters, with a **65-degree half-angle (130-degree opening)**. Cannon visual dimensions are one quarter of the previous placeholder dimensions (2.25-meter barrels), fitted to the hull openings. Weapon range, speed, damage, reload, and cone angles retain their existing values. The visual barrel pivots around the muzzle without rotating the allowed cone. Visual pitch/bank carries both slots with the ship.

[`rusty_cannon.tres`](../../resources/weapons/rusty_cannon.tres) is the shared, immutable tier-one definition:

| Setting | Current value |
| --- | ---: |
| Targeting range | 200 meters |
| Damage | 5 |
| Launch speed | 500 meters/s (current authored trial, with a reference speed of 200 m/s after unit conversion) |
| Downward acceleration | 30 meters/s² |
| Maximum projectile lifetime | 8 seconds |
| Reload per cannon | 2 seconds |
| Kestrel health | 250 |
| Wreck gravity scale | 0.2 (19.6 meters/s² with current project gravity) |
| Wreck lifetime | 25 seconds from first ground contact, or 45 seconds from death if never grounded |

Health, reload, gravity, lifetime, and engagement distance are provisional tuning. Tier compatibility requires exact matching for any positive tier. Lower-tier equipment in higher-tier slots is not currently allowed.

## Aiming and impact

[`Ballistics`](../../scripts/combat/ballistics.gd) solves for the earliest positive interception time, assuming the target continues at its current world velocity. It partitions the scalar interception polynomial using derivative roots, then performs bounded bisection within monotonic intervals. Boundary residual checks include tangent solutions. It rejects invalid inputs and solutions whose launch speed fails its residual check.

The current target and predicted intercept must both be within the weapon's configured range of the muzzle, currently 200 meters for Rusty cannon. The **initial launch vector**, including elevation and lead, must fit the slot cone. The weapon does not test obstruction by its own hull or balloon. It does not switch to a high lob when the earliest solution fails range or cone checks. Barrel aim and projectile motion use the same launch vector.

At the converted 200 m/s reference speed, a stationary equal-height 600-meter target takes about 3.08 seconds to reach, with a 35.7-meter rise. A 1000-meter target takes about 5.49 seconds, rising 112.9 meters. These reference trajectories remain solver fixtures. The current authored 500 m/s trial produces substantially flatter, faster shots. Launch speed is not constant speed along the arc. The cannonball has no drag, homing, inherited shooter velocity, or speed-dependent damage. Target acceleration after launch can cause misses.

[`ProjectileController`](../../scripts/combat/projectile_controller.gd) advances all shots in one physics step using the constant-acceleration equation. Each shot owns local position, velocity, gravity, lifetime, captured source faction, a weak shooter reference for collision exclusion, and one shared-mesh visual. No rigid bodies, projectile areas, or per-shot timers are used.

The shared [tracer mesh](../../resources/weapons/cannon_tracer_mesh.tres) is a slim 18-meter capsule, 1.4 meters wide, with warm amber emission. Its long axis follows the current ballistic velocity each physics tick. Its rear tip sits at the shot position, extending the streak forward from the muzzle without overlapping the cannon. Journey enables restrained HDR glow for the bright tracer. The streak is visual only. It adds no light nodes or collision volume.

Each physics step sweeps its short arc chord through Godot's physics space. A curvature bound of `gravity * dt² / 8` subdivides unusually long steps to keep chord error below 0.1 meters. At the current 30 Hz rate and authored gravity, one ray per shot suffices. The first collision consumes the shot. An opposing ship takes five damage. Allied ships and island colliders consume it without damage. Only the firing ship is excluded. A shot remains independent after its shooter or target disappears.

Range is targeting distance, not arc length. Misses continue falling until impact or the eight-second lifetime, and can hit another ship beyond targeting range. Terrain and water have no colliders. The visible tracer uses point collision, and chords test against the current physics snapshot. This is not continuous collision between arbitrary-speed moving shapes. Supported ship speeds and crossing targets are covered by the focused check.

## Targeting and movement

### Queryable vertical role

`Airship.vertical_combat_bias()` returns the average Y component of its unique, valid, normalized `preferred_combat_positions`, from -1 (targets below) to +1 (targets above). Horizontal bearings contribute zero. Opposite bearings cancel. Unknown names and duplicates are ignored, and an empty list is neutral. This describes the authored role independently of faction, scene readiness, current target, or visual banking. It does not measure the currently equipped weapons or their live firing solutions. `ShipCombat.vertical_bias(positions)` exposes the same calculation for callers with a direction list.

`Airship.preferred_altitude_side()` returns -1 when upward bias is at least 0.5, so upward shooters approach from below their opponents. Otherwise it returns +1, giving downward and neutral roles the upper approach. A single upper diagonal qualifies. A weak upward option mixed with several horizontal bearings may remain neutral. All five upper bearings (`front_up`, `left_up`, `up`, `right_up`, `back_up`) and their lower counterparts (`front_bottom`, `left_bottom`, `bottom`, `right_bottom`, `back_bottom`) are supported alongside the eight horizontal bearings.

Spawning uses the independent authored `Airship.spawn_layer` choice. See [ship spawning](ship_spawning.md). These authored-role queries remain independent of runtime steering. Combat positioning uses the authored positions described below, and never repositions the fleet marker.

### Target selection and navigation

[ShipCombat](../../scripts/ships/ship_combat.gd) selects and retains an eligible hostile independently of navigation. The nearest-first selector accepts targets within the sphere plus its entry band. Choosing a far-side target does not require increasing local waypoint distance. Empty or utility-only loadouts continue ordinary movement. Authored positions are accepted independently of gun cones and ranges. Unknown names and duplicates are ignored. Kestrel enables `front_left`, `left`, `left_back`, `back_right`, `right`, and `front_right`, giving both broadsides symmetric options.

**Preferred Combat Positions** describe where the enemy belongs relative to the attacking ship in fixed fleet axes: front is Z-, right is X+, and up is Y+. `bottom` places our ship above the enemy. These axes follow neither hull's yaw. **Engagement Distance** defaults to 150 meters, with 20% tolerance. The nominal distance is tried first, then 80% and 120% when needed. Small angular variation spreads destinations around each enabled direction. The position follows the target's translation and survives floating-origin shifts.

[ShipNavigation](../../scripts/ships/ship_navigation.gd) owns the selected attack position, its target-relative offset, intermediate waypoints, and final movement request. It retains an available position instead of switching sides whenever another becomes nearer. If the retained point fails sphere, hull, island, or local-route checks, it tries another point for that position and every other enabled position. An endpoint must fit inside the sphere with hull clearance. A distant endpoint is approached through local steps. Transit can cross other sectors, with courses around the target's hull. If a direct step is blocked, a bounded 32-candidate search looks for a clear step that reduces distance to the endpoint. This is local routing, not a complete path solver.

When every option fails, the same navigator chooses an ordinary random navigation coordinate without attack scoring. The ship retains its selected enemy and retries attack positions at the normal three-second combat goal interval, or sooner on arrival or target change. Mounted weapons keep acquiring and firing independently, including pass-by shots when enabled. An invalid retained attack point triggers immediate reconsideration. Collision clearance, containment, and native flight limits take precedence over attack positioning.

Engagement distance is authored independently of weapon range. Authors must pair spacing and positions with a suitable loadout. Movement never consults gun cones or adjusts spacing when gun range changes. MountedWeapon still validates current distance, predicted intercept distance, lifetime, and the exact launch cone before firing. A valid attack position does not guarantee a shot, particularly while a hull is turning. Equipment replacement/removal clears pursuit through the existing signal, and an unarmed ship returns to ordinary travel.

`check_ship_flight.gd` covers fixed axes despite hull and target yaw, independence from gun cones/range, flexible distance, alternate broadsides, island and sphere rejection, wandering with pass-by fire, retry recovery, disarming, translation, and rebasing. Its moving approach fixture supplies repeated firing opportunities with a 200-meter weapon range. Both Manta factions start below a designated target, including a start directly underneath, with a separate passer available. They check climbing to firing altitude, main-target launches, pursuit retention, and containment. Upper authored positions use the same rule to approach below a target.

Combat is a fleet-wide encounter state while pending spawns or living hostiles remain. The persistent fleet marker keeps moving at its normal travel pace throughout combat. Clearing the encounter refreshes ordinary destinations without restarting or changing marker speed. Destination containment is strict. Physical momentum and contacts may cause temporary displacement.

Mounted weapons own a firing target independently of ship target selection. Pursuit changes and target removal preserve each weapon's staggered search deadline, avoiding fleet-wide search bursts. At a staggered 0.2-second acquisition check they prefer a shootable main target, then a retained passer, then nearby alternatives. Reload runs independently: a ready weapon can keep firing at its retained target between acquisition checks. Every shot validates current range, target velocity, and the actual mount cone with a fresh ballistic solution. A closer passer alone does not replace a usable retained target. Successful pass-by shots do not change the ship's designated pursuit target, attack position, or navigation destination. Disabling pass-by fire permits only the main target. Cooldowns remain per weapon, with no catch-up burst after a stall.

Fallback searches reject out-of-range candidates and those outside a conservative cone expanded for gravity and target lead before ranking. They keep only the nearest untried candidates needed by the remaining four-attempt budget, including main/retained attempts in that budget. Equal distances use stable ship IDs. Failed-attempt IDs persist across searches so moving, unreachable nearby targets cannot starve farther candidates. Exhaustion, successful shots, main-target changes, and removals clear the appropriate state. The search may rescan once if its remaining candidates disappeared or left range/cone. It never sorts the full candidate set. The cone filter can only reject impossible shots. Exact firing permission still belongs to the ballistic solution and MountedSlot.

## Ownership and cleanup

[`Journey`](../../scripts/world/journey.gd) orchestrates each physics step:

1. Remove previously queued deaths, process requested friendly spawns and distance-based encounters, snapshot ships, and update the fleet marker and combat state.
2. Rebuild the derived combat-query snapshot, evaluate targets and advance each ship's shared navigator, and calculate ship separation from the common movement snapshot.
3. Advance existing projectiles and resolve damage before submitting control forces, so a lethal hit prevents thrust in this tick.
4. Constrain surviving ships to bounded, obstacle-aware navigation requests, submit their thrust/lift/drag forces and yaw torque once, and let their weapons fire. New shots begin traveling on the following tick.
5. Unregister destroyed ships from gameplay while retaining their wreck bodies, then rebase and update scenery/progression.

Force submission does not immediately move the hull. Godot/Jolt integrates rigid-body motion and resolves contacts for the next physics snapshot. Avoidance, aiming, and projectile queries read the latest completed body state. Aiming and debug velocity use the body's `linear_velocity`. Living hulls lock X/Z rotation while the visual child banks/pitches. Ship control does not overwrite physical transforms or velocities each frame, and projectiles remain scripted point sweeps.

Airship owns health and emits one death signal. At zero health it stops all flight control (thrust, lift, steering, braking, and deliberate lateral drag), applies its exported **Wreck Gravity Scale**, restores default engine damping, unlocks pitch/roll, allows sleeping, and starts every authored death-smoke node. Existing linear/angular velocities are preserved. The gravity multiplier defaults to 0.2: 19.6 meters/s² instead of the full converted project gravity of 98 meters/s². This slows descent without introducing a velocity clamp or changing live flight, global gravity, or projectile gravity. During falling/settling the body retains its collider and can exchange momentum with ships, islands, and full-detail terrain. Projectiles hitting it are consumed without further damage.

Death immediately prevents targeting/firing. Journey removes list entries after active loops, updates fleet membership and living spawn counts, and invalidates pursuit, firing-target, and query references. Wrecks remain registered with FloatingOrigin until expiry. Airship owns physics-clock settling and cleanup: `wreck_settle_seconds` defaults to 3, `wreck_lifetime` to 25 seconds after first upward static-ground contact, and `wreck_airborne_lifetime` to 45 seconds without contact. The first ground contact immediately stops and hides all smoke. It freezes while supported after settling and disables hull collision. The camera falls back to fleet focus on death or removal and cannot select wrecks. IDs are allocated monotonically through Journey. Spawning uses a dedicated RNG and bounded attempts against ship/island clearance. WreckController controls visibility from the actually published terrain detail: coarse or unloaded ground hides the wreck, and full source detail reveals it. Wrecks do not force refinement. Terrain patches own their native colliders. See [terrain collision](terrain.md#wreck-collision-and-visibility). Water has no surface collision or buoyancy.

`health_changed` is the health owner's notification contract, including for later presentation. The slice has no health UI. Synchronous damage from a listener cannot repeat the death notification. `ShipCombat.clear_target()` clears target and bearing preferences. Airship owns the subsequent combat-to-travel handoff, including after equipment changes. A zero-duration Journey step only drains queued deaths. It does not submit forces, fire weapons, spawn, or stream. It does not pause native physics. Disabling Journey callbacks also leaves inertia active. Stationary test fixtures freeze their bodies explicitly.

The projectile root, including its shared shot-smoke batches, is registered once with FloatingOrigin. Shots store positions relative to that root. Both ray endpoints use its current transform. A rebase changes neither velocity nor gravity/lifetime and never creates a long sweep between old and new world coordinates. Scene ownership releases projectiles, visuals, and subscriptions on exit.

`Journey.combat_enabled = false` isolates the existing movement checks from combat and automatic encounters. Explicit friendly picker requests remain available. It is a validation setting, not an in-game pause feature. Navigation debug starts disabled. F3 toggles the purple navigation sphere, goals, and velocity arrows, using red goals for combat and cyan for ordinary travel. The purple marker cube remains visible independently.

## Spatial filtering and measurement

[`CombatPerception`](../../scripts/combat/combat_perception.gd) is a Journey-owned, derived spatial view of living registered ships. It supplies nearby-hostile queries and validity checks. It neither owns ships nor selects pursuit or firing targets. Its 1000-meter cells are rebuilt each combat tick. Each searching ship lazily shares one nearby-candidate query among its mounts, with a radius covering the longest equipped range plus muzzle offsets. Individual mounts still filter exact range/cone. Death is checked immediately. Unregistering removes membership, the stored cell entry, and cached queries before deletion. The snapshot records each ship's cell so removal remains correct if its position changes afterward. Subsequent rebuilding incorporates spawns, loadout changes, and origin shifts. Snapshot reuse is limited to one combat tick.

ShipAvoidance evaluates each unordered candidate pair once and adds opposite corrections to the two ships. Sorted index traversal preserves accumulation order, and clamping happens after all contributions. The predictive capsule math stays inside the traversal loop because the measured per-pair helper overhead erased the first trial's saving. The old directed calculation exists only as an independent regression oracle in check_combat.gd.

Profiling the 220-ship scene justified two ordinary spatial filters. ShipAvoidance builds a three-dimensional cell map from each physics snapshot. Cell size conservatively covers the largest hull and relative speed over the existing two-second avoidance horizon. Neighbor indices are sorted to preserve the original accumulation order. Before calculating the closest capsule segments, an enclosing-sphere check rejects pairs that cannot interact at the predicted instant. The full-scan calculation remains available as a regression oracle for neighbor filtering.

IslandSpawner owns a two-dimensional cell map of loaded island centers. Its conservative search radius comes from ShipNavigation's conservative turn/braking horizon and hull/island clearance. It rebuilds after loading, unloading, or rebasing. The navigation algorithm still performs its exact height and segment tests. Neither filter changes the steering rules or creates another authoritative ship/island registry.

In a short headless 220-ship component sample on the development workstation, ship avoidance decreased from 7.74 to 4.67 ms and island navigation from 8.57 to 1.17 ms per step. These historical scripted-flight samples explain the optimization, not an endgame frame-rate guarantee. `Journey.profile_steps` enables separate decision/query, avoidance, navigation, force-submission/candidate-query, projectile, weapon, and cleanup/streaming timings. The navigation phase includes local goal selection, combat scoring, containment, and island route checks. It is not the removed island-detour controller. The `Journey.StepPhase` enum defines the timing slots shared by runtime and benchmark. The [combat performance integration](combat_performance.md) records the current comparison. Native rigid-body integration/contact solving happens outside this script timer. Normal play does not enable these timers.

## Staged battle reference

[`staged_battle.tscn`](../../scenes/world/staged_battle.tscn) lives beside Journey and inherits its complete scene. Open it in Godot and press **F6** to run it. To use F5 instead, select it as the project's main scene. The default main scene remains `journey.tscn`, with its three starting Kestrels and ordinary distance-based waves.

The reference replaces the starting fleet with random ships from Journey's **Available Ships** catalog, currently Kestrel, Swift, Manta, and Bastion. Each catalog entry has equal selection probability. Both factions target 100 living ships and automatically replace casualties, adding at most two ships per faction per physics tick. A failed placement waits half a second before retrying. Ships retain their authored health, weapons, movement, and death behavior. Top-ups choose clear visible positions around the marker inside 70% of the fleet radius, checking loaded colliders and same-tick hull reservations. This setup bypasses concealed spawning to sustain the reference battle. Manual picker additions can exceed the automatic population target.

Select the scene root to edit **Battle Setup**: **Faction Limit**, **Spawns Per Faction Per Tick**, and **Battle Seed**. Seed 715932 is the default for repeated comparisons. Zero selects new randomness each run. The seed fixes the composition and placement random sequence, not exact native-physics outcomes. The inherited **FleetController** authors a 1400-meter minimum sphere radius, **OrbitCamera** starts at 2800 meters, and **Encounters** disables ordinary waves. All other settings come from Journey.

Terrain and its colliders, water, clouds and dissolve, islands, sky and fog, lighting and shadows, projectiles, muzzle/death smoke, wreck cleanup, streaming, floating origin, camera input, and the full UI remain part of the scene. Changes to Journey's composition and shared content also reach this inherited reference. Normal rendering and the project 30 Hz physics rate remain active. Compare performance using the same scene settings, ship content, seed, view, display size, debug visibility, and run duration. This interactive reference has different content and workload from the separate 70 vs 150 Kestrel scale benchmark below.

`check_staged_battle.gd` verifies the normal Journey setup separately, then checks the inherited world systems, faction limits, mixed ship types, clear spawn positions, automatic top-ups, replacement IDs, disabled waves, rebasing, and live combat. Run it with the isolated environment and external log required by AGENTS.md, using `--headless --fixed-fps 30 --script res://scripts/tools/check_staged_battle.gd`. For a rendered check, omit `--headless`, set an external `AERWYTH_CAPTURE_DIR`, and append `-- --visual`.

## Validation

Select checks using [AGENTS.md](../../AGENTS.md). These commands are available coverage, not a required suite for every edit. Follow its serial launches, process-local APPDATA isolation, absolute project paths, and unique external logs. For weapon/impact changes, run the default fixtures:

```text
--headless --path <absolute-project-path> --fixed-fps 30 --script res://scripts/tools/check_combat.gd --log-file <external-log-file>
```

All physics checks and benchmarks use the project's accepted 30 Hz baseline. Scripted deltas and timed scenarios follow that rate. There are no alternate-rate loops or physics overrides. `--fixed-fps 30` accelerates functional runs without changing the physics setting. `check_combat_targeting.gd` checks spatial queries against full scans, shortlist ordering/fairness, removed targets, independent firing/acquisition clocks, and conservative cone rejection against the full solver.
